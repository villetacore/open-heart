# OpenHeart — ТЗ на иконки, портреты и игровые ассеты

Связанный документ: [план законченной версии](RELEASE_PLAN_2026-09-20.md).

Статус: производство ресурсов. Часть иконок и портретов уже сгенерирована; актуальные файлы и условия интеграции перечислены в `ART_ASSET_MANIFEST.md` и `ART_HANDOFF.md`. Предложения ниже не означают, что весь контент реализован.

## Художественное направление

**Обязательный канон владельца: игра про фембоев.** Игровые герои — взрослые мужчины с женственной и андрогинной внешностью. Сохранять этот образ в портретах, костюмах, ключевых иллюстрациях и рекламных материалах. Не подменять героев брутальными типовыми бойцами или женскими персонажами. Различать классы по силуэту костюма, характеру и снаряжению, сохраняя женственные детали: ленты, украшения, макияж, кружево, сердца. Образы боеспособные и выразительные, без карикатурности.

Неоновая готика, читаемые крупные формы, тёмный металл и камень, локальные светящиеся акценты. Использовать существующие `game/assets/concepts/` как справочник. Избегать мелкого орнамента, который пропадает при уменьшении, и одинакового свечения на всех объектах.

Иконки предметов/умений: согласованная стилизация под пиксельную игру, единый ракурс, один предмет или символ на изображение, чёткий контур. Важнее читаемость, чем количество деталей. Если после генерации требуется пиксельная нормализация, делать её единым воспроизводимым этапом.

Рамки, подписи, счётчики, клавиши, редкость и затемнение восстановления рисует интерфейс. Не запекать их в картинки. Геометрические системные значки и масштабируемые рамки удобнее делать вектором/средствами движка; генерацию использовать для предметных изображений, персонажей и художественных элементов.

## Размеры и контракты

| Тип | Авторский материал | Предлагаемый runtime-формат | Проверка |
|---|---|---|---|
| Иконка предмета/умения | Квадратный отдельный исходник достаточного разрешения | PNG RGBA 128×128; показать в слотах 64 и 48 px | Узнаётся при 48 px, чистый alpha, силуэт не касается границы |
| Иконка перка | Крупный простой символ | PNG RGBA 128×128 или вектор для простой геометрии | Отличима от соседних узлов в малом масштабе |
| Портрет класса | Погрудный рисунок, единый поворот/свет | PNG 512×512 | Корректный кроп; лицо и костюм сохраняются между изображениями |
| Портрет NPC | Погрудный рисунок с выражением характера | PNG 512×512 | Читается в диалоге, совпадает с игровым персонажем |
| Игровой спрайт | Референс персонажа + отдельные контролируемые позы | Существующий контракт атласа после проверки `SPRITE_SPEC.md` и animation-профиля | Одинаковая опорная точка, масштаб, порядок кадров, отсутствие обрезки |

Для иконок оставить приблизительно 10% безопасного поля. Конкретный filtering выбрать на пробной партии: nearest для нормализованного пиксельного материала; для гладких портретов — подходящая фильтрация без смешения стилей внутри одной категории.

Не рассчитывать, что генератор сразу выдаст технически точную сетку анимации. Сначала зафиксировать персонажа, затем получить ключевые позы и собрать атлас под реальные строки/кадры кода. Проверить idle → move → attack → pain → death в движении. В просмотренном атласе жреца уже есть разные состояния; его не следует автоматически заменять только ради новой генерации.

## Шаблоны промптов

### Иконка

> Create a single readable game inventory icon of [OBJECT AND FUNCTION] for OpenHeart, a neon gothic first-person action RPG. Dark worn metal, restrained [ACCENT COLOR] glow, strong simple silhouette, stylized pixel-art-compatible forms, consistent upper-left lighting, three-quarter view, centered composition, generous clean padding. Transparent background. No text, no letters, no numbers, no border, no UI panel, no collage, no secondary objects. Must remain recognizable at 48 pixels. Match the supplied approved reference style.

Для магического действия заменить ракурс предмета на ясный символ движения/воздействия. Не просить три эффекта в одной маленькой иконке. Наличие прозрачности проверять по alpha, а не по нарисованному шахматному фону.

### Портрет

> Character selection portrait for OpenHeart, a neon gothic first-person action RPG. [CHARACTER ROLE, FACE, COSTUME, DISTINCTIVE FEATURE]. Bust portrait, readable facial expression, grounded proportions, dark charcoal and plum palette with restrained [ACCENT] light, consistent three-quarter pose and upper-left key light, stylized painted pixel-art-compatible finish. Simple dark background with clear separation from the silhouette. No text, no frame, no logo, no UI. Preserve the identity, costume and material language of the supplied character reference.

### Локация как референс

> Environment reference for [DISTRICT], a playable neon gothic 2.5D first-person level. Show a clearly readable main route toward [LANDMARK], a visible side loop and one playable elevated route. Distinct foreground, middle ground and background. Dark stone and worn metal, restrained local [ACCENT] light, readable enemies and traversable surfaces. Keep combat space clear. No UI, no text. Favor modular geometry that can be rebuilt in the existing game engine.

Референс локации не заменяет план карты, коллизию и расстановку врагов. Приоритет за проверенным маршрутом.

## Подключение к игре

1. Добавить необязательные `icon`/`portrait` в нужные определения контента с совместимым значением по умолчанию.
2. Завести явную таблицу `entity id → resource path`; не угадывать имя файла по русскому названию.
3. Создать один общий UI-компонент слота; состояние задаёт код, изображение остаётся неизменным.
4. Добавить проверку существования и размеров ресурсов. В разработке показывать явную диагностическую заглушку; в релизном контенте обязательные ссылки должны проходить проверку.
5. Сохранять в сейве id сущности, не копию графического пути. При изменении id предусматривать миграцию.
6. Проверить импорт и экспорт PNG, а также данных RON/JSON/TOML на чистой экспортированной сборке.

Предлагаемая структура новых файлов:

```text
game/assets/icons/abilities/<id>.png
game/assets/icons/items/<id>.png
game/assets/icons/perks/<id>.png
game/assets/portraits/classes/<id>.png
game/assets/portraits/npcs/<id>.png
```

Исходники хранить отдельно от runtime-ресурсов; проверить фильтры экспорта, чтобы большие source-sheet и концепты не попадали в релиз без необходимости.

## Учёт и приёмка

Для каждого ресурса вести: id, категория, связанная игровая сущность, описание смысла, исходник, готовый путь, версия промпта/референса, происхождение, размеры, статус проверки и места использования.

Статусы: planned → generated → reviewed → processed → integrated → verified. Только `verified` закрывает задачу.

Проверка каждого набора:

- [ ] Нет текста, рамок, случайного фона и обрезанного объекта.
- [ ] Палитра, контур, свет и степень детализации согласованы с образцом.
- [ ] Значки различимы в реальном размере, в том числе без опоры только на цвет.
- [ ] Умение визуально передаёт своё действие; изображение предмета соответствует описанию.
- [ ] Портрет сохраняет идентичность игрового персонажа.
- [ ] Спрайт не прыгает относительно опорной точки и не меняет размер между кадрами.
- [ ] Ресурс подключён к настоящей сущности и проверен в интерфейсе/сцене.
- [ ] Экспортированная игра загружает файл; нет предупреждения о недостающем ресурсе.
