# Производство контента

[Навигация](README.md) · Состояние на 27.09.2026.

## Что где редактировать

| Контент | Источник | Ограничение |
|---|---|---|
| Кампания | `game/presets/core/` | Встроенный пресет; изменения влияют на hash совместимости |
| Задания и диалоги | `quests`, `dialogues`, `npcs` | Связи через стабильные ID, флаги и условия |
| Оружие | `weapons`, `weapon_mods` | Восемь видов оружия закреплены кодом; девятый требует реализации |
| Прокачка | `classes`, `perks`, `synergies`, `player_abilities` | Новое значение существующего поля проще новой механики |
| Враги | `enemies`, `abilities`, `affixes`, `statuses` | `abilities` — способности врагов, не игрока |
| Экономика | `items`, `recipes`, `loot` | Проверять источники и расходы ресурсов вместе |
| Подземелье | `dungeon` | Темы, пулы, архетипы комнат; генератор остаётся в Rust |
| Город | карта пресета, NPC, world changes | Спавны карты и резервный `level` — разные источники |
| Изображения | `game/assets/` | PNG + Godot resource, ссылка из данных и импорт |
| Локализация | поля RU/EN соответствующих записей | Проверять обе версии и длинные реплики |

Точные структуры: [форматы](../DATA_FORMATS.md), [пресет v2](../PRESET_FORMAT_V2.md), [индекс кода](../INDEX.md). Эти справочники читать вместе с актуальными структурами Rust: примеры могут отставать от реализации.

## Обязательный цикл партии

1. Определить игровую цель: что игрок делает, что понимает и какое последствие видит.
2. Выбрать существующую механику и ID с префиксом партии. Не менять ID уже выпущенного задания без миграции сохранений.
3. Подготовить JSON, RU/EN, награды, зависимости, стартовую точку и условия окончания.
4. Синхронизировать изменённые stem в RON. Runtime предпочитает RON: редактирование только JSON может ничего не изменить в игре.
5. Проверить ссылки, цепочку зависимостей, повторную сдачу, загрузку сохранения, недоступность преждевременного финала.
6. Подключить изображения и проверить их в диалоге. Успешное открытие PNG отдельно не проверяет интерфейс.
7. Проверить свежую игру и подходящее старое сохранение; затем экспорт. Отдельно указать непроверенные шаги.
8. Обновить инвентаризацию, отчёт партии и документацию механики, если она изменилась.

Из корня репозитория:

```powershell
cargo run -p openheart-core --example sync_preset -- game/presets/core quests dialogues
cargo test --workspace
python tools/audit_project.py
```

`sync_preset` сначала проверяет обратное чтение сериализованного RON, затем записывает выбранные файлы. Это не валидатор всех игровых зависимостей. Старый `preset_migrate` тоже существует; для новых партий выбрать один маршрут и не запускать оба без необходимости.

Редактор Godot сохраняет JSON. Пока его сохранение не синхронизирует RON, после работы в редакторе нужен тот же шаг конвертации. Перед изменением ожидаемого hash проверить содержимое diff: hash учитывает текст файлов, поэтому табы вместо пробелов тоже меняют его. Несовпадение hash само по себе не доказывает различие игровых значений.

## Как проектировать задания

Задание описывает действие, цель, количество, зависимости и награду. Диалог предлагает принятие/сдачу, проверяет состояние и применяет эффекты. Условия не должны существовать только в тексте реплики. Событийная цель обычно считает действия после принятия; не обещать игроку зачёт прежних действий без проверки конкретного обработчика. `clear_dungeon` имеет отдельное поведение учёта истории.

Для каждой цепочки записать стартового NPC, необходимые предыдущие задания, минимальную глубину, условия сдачи и доступность повторного разговора. Различать выдачу предмета, открытие косметики, флаг и изменение города. Косметика не означает замену мировой модели.

Эталон партии: [«Свет для общего стола»](../CONTENT_UPDATE_SHARED_TABLE.md), [генератор записей](../../tools/add_evening_content.py), [проверки](../../core/src/data/evening_tests.rs). Четыре задания последовательно используют реле, эхо, разговор с Ивом и разговор с Рэном; финал ставит стол в городе. Цепочка требует прогресса в личных историях соседей, а эхо встречается с глубины 3. Это не стартовый эпизод на несколько минут.

## Изображения и единый стиль

Художественное направление: романтическая готика квартала, холодная ночная среда и тёплые жилые места; узнаваемая одежда, силуэт и палитра каждого взрослого героя. Подробные правила и промпты: [план графики](../ART_AND_CONTENT_PLAN_2026-09-27.md), [ТЗ](../ART_PRODUCTION_BRIEF.md).

Иллюстрация, портрет и мировой спрайт служат разным задачам. Иллюстрация передаёт сцену и отношения; портрет — личность в разговоре; спрайт — узнавание на игровой дистанции. Сейчас эти уровни частично расходятся, поэтому следующая партия должна связать уже существующие образы, особенно шесть соседей и боссов.

Для каждой генерации сохранять точный промпт, использованные референсы, путь результата и статус: создано → подключено → проверено в движке → проверено в экспорте. Пример — манифесты в [каталоге иллюстраций](../../game/assets/illustrations/neighbors/).

Диалоги поддерживают явные `res://assets/...png` и `.tres`; старые ID портретов продолжают работать. Не использовать абсолютные пути компьютера или `..`. Панель иллюстрации — 700×390 с сохранением пропорций; длинный текст имеет отдельную прокрутку. При смене реплики проверять очистку старой текстуры.

Проверка: `powershell -File tools/verify_art_wave03.ps1`, затем [runtime smoke](DEVELOPMENT.md). Статическая проверка не гарантирует правильную композицию, атласный регион или попадание ресурса в экспорт.

## Критерий готовности

Партия готова, когда достижима в обычной игре, имеет понятную мотивацию, корректные награды и локализацию, переживает сохранение/загрузку, не даёт повторных наград, визуально читается и проверена в целевой сборке. Количество новых сцен само по себе не измеряет качество партии.
