# Сеть, сервер и терминальный клиент

[Навигация](README.md) · Состояние на 27.09.2026.

## Компоненты

| Компонент | Роль |
|---|---|
| Godot + Rust GDExtension | Графический клиент, локальная игра и сетевое представление |
| `openheart-core` | Данные, общие правила, чистая симуляция, WASM ABI |
| `oh-server` | Комнаты, сессии, тики симуляции, сетевые сообщения |
| `oh-master` | Реестр серверов, авторизация и инфраструктура подключения |
| `oh-probe` | Проверка доступности инфраструктуры |
| `oh-content-hash` | Расчёт hash содержимого для проверки совместимости |
| `openheart-terminal` | Rust-клиент с offline/host/server маршрутами |

Go использует wazero для исполнения `core.wasm`. Симуляция комнаты работает с шагом 20 Гц. Если используется stub, он обслуживает ограниченную модель игроков и движения: полноценные враги, урон и добыча в нём отсутствуют. Доступный порт не равен работающей игровой симуляции.

## Границы авторитетности

Общее ядро уменьшает расхождения, но не делает весь геймплей автоматически серверным. Значительная часть игрового поведения находится в Godot-клиенте. Например, локальный крафт вызывает core над локальным инвентарём; это само по себе не серверная транзакция.

Полную эквивалентность Godot и `core::sim` считать отдельной задачей. Для каждой механики необходимо назвать владельца состояния, команду, проверку на сервере и способ восстановления после переподключения. Пока такой маршрут не проверен, не обещать одинаковую экономику и бой во всех клиентах.

Протокол имеет собственную версию, независимую от версии save. Текущее значение протокола — 1; save — 4. Hash пресета учитывает текстовые файлы данных с нормализацией CR, но не PNG, поэтому одинаковый hash не гарантирует одинаковые картинки.

## Терминал

Offline использует чистую симуляцию. `--host` запускает собственный сервер и требует реальное ядро для геймплея; процесс клиента управляет своим дочерним сервером. `--server` подключается к указанному адресу. Порты по умолчанию у маршрутов отличаются: сверяться с параметрами запуска, а не предполагать один порт для всех случаев.

Соло-сохранения находятся в `.openheart-terminal/solo-PRESET.json`; гостевые разделены по адресу, пресету и имени. Авторизованный режим использует серверное состояние персонажа. Это не перенос полного Godot-снимка игрового мира.

Терминал не воспроизводит все альтернативные выстрелы, снаряды/сплэш, модификации оружия, hazards и модификаторы сборки графического клиента. Нет полноценной вертикальности и всех пространственных хитбоксов. Использование аптечки ограничено отсутствием нужной серверной команды; расходовать её без лечения нельзя. Подробные команды и актуальные исключения: [terminal/README.md](../../terminal/README.md).

## Хранение и развёртывание

Сервер использует SQLite и настройки из дефолтов, файла, `OH_*` и флагов CLI. Конкретные имена параметров и последовательность запуска приведены в [server/README.md](../../server/README.md). TLS завершается внешней инфраструктурой; встроенную защиту транспортного канала не предполагать.

Основные исходники: [server/internal](../../server/internal/), [протокол](../../protocol/schema.md), [симуляция](../../core/src/sim/). Старый [план мультиплеера](../MULTIPLAYER.md) содержит историю этапов и не заменяет проверку текущих обработчиков.

## Что проверять перед сетевым релизом

Подключение двух клиентов, совпадение данных, движение и бой, награды без дублирования, выход/возврат, обрыв соединения, сохранение авторизованного персонажа и поведение несовместимой версии. Проверять с реальным WASM и целевыми клиентами. Прохождение Go unit tests не подтверждает эти сценарии целиком.
