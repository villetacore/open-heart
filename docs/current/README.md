## Источники истины

1. Поведение — реализация и воспроизводимый тест, а не комментарий «планируется».
2. Формат — Rust-структура десериализации и её дефолты. Примеры: [config.rs](../../core/src/data/config.rs), [dialogue.rs](../../core/src/data/dialogue.rs), [map_def.rs](../../core/src/worldgen/map_def.rs).
3. Данные runtime — выбранный пресет с приоритетом RON → JSON → TOML для одного stem. JSON удобен для редактирования и инвентаризации, но не перекрывает существующий RON.
4. Проверка — конкретная команда, результат и границы. «Тесты прошли» не означает полный ручной плейтест и готовый экспорт.
5. При конфликте нового документа со старым планом ориентироваться на этот раздел и актуальный код.

## Правила поддержки документации

- Новая механика меняет соответствующую страницу этого раздела; новая партия контента получает отдельный отчёт со статусом интеграции.
- Количества обновлять через `python tools/audit_project.py`; не копировать в десяток таблиц без даты.
- Изменение поля данных: обновить структуру, парсер/валидацию, пример и правила совместимости.
- Технические ограничения писать рядом с возможностью. Соло, сеть и терминал не считать равнозначными по умолчанию.
- Датированные планы и `ART_HANDOFF.md` читать как историю конкретных работ, а не как действующее разрешение или запрет на изменение кода.
