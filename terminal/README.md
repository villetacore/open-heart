# OpenHeart Terminal

Отдельный Rust-клиент `oh-terminal`, без Godot и графического окна. Карта рисуется
символами сверху, игра обновляется в реальном времени на 20 Гц. Он использует
`openheart-core`, пресеты из `game/presets` и существующий WebSocket-протокол Go-сервера.

## Запуск

Из корня репозитория:

```sh
cargo run -p openheart-terminal
```

В меню доступны одиночная игра, запуск собственного Go-сервера и подключение по
адресу. Можно сразу выбрать режим:

```sh
# Одиночная игра: симуляция Rust внутри процесса клиента
cargo run -p openheart-terminal -- --offline

# Свой Go-сервер дочерним процессом + автоматическое подключение
cargo run -p openheart-terminal -- --host

# Подключение к уже работающему серверу
cargo run -p openheart-terminal -- --server ws://127.0.0.1:7777/ws --nick Alex

# Сразу в подземелье, класс 3 (Оператор)
cargo run -p openheart-terminal -- --offline --world delve --depth 2 --class 3
```

Поддерживаются Windows Terminal, PowerShell, Linux/macOS-терминалы с UTF-8.
Рекомендуемый размер — от 110×35; маленький терминал обрабатывается без падения.
Обычный запуск требует интерактивные stdin/stdout. В перенаправленном выводе
используйте `--headless`.

## Собственный сервер

Для первой сборки хоста нужны Go и Rust с WASM-таргетом:

```sh
rustup target add wasm32-unknown-unknown
cargo build -p openheart-core --target wasm32-unknown-unknown --features abi --release
go -C server build -o oh-server.exe ./cmd/oh-server
```

На Linux/macOS назовите бинарник `oh-server`. При `--host` недостающие стандартные
артефакты собираются автоматически, если клиент запущен из исходников. Уже имеющиеся
артефакты не пересобираются: после изменения ядра/сервера выполните команды выше.
Без настоящего `core.wasm` хост не запускается на заглушке.

По умолчанию сервер слушает `127.0.0.1:7788`. Для игры в LAN:

```sh
cargo run -p openheart-terminal -- --host --listen 0.0.0.0:7788 --nick Host
# На другом компьютере, подставив адрес хоста:
cargo run -p openheart-terminal -- --server ws://192.168.1.10:7788/ws --nick Friend
```

`--host --master https://MASTER` передаёт Go-серверу режим пати/релея. Полученный
код пати показывается в заголовке. Для прямого подключения через релей можно
использовать его WebSocket endpoint. Разрешение пати-кода и список серверов в
терминальном меню пока не реализованы.

`--server-bin PATH` и `--core-wasm PATH` задают готовые артефакты. Для переносимой
папки положите рядом `oh-terminal`, `oh-server`, `core.wasm` и каталог `presets`.
Для клиента, который только подключается, сервер и WASM не нужны.

Готовую переносимую Windows-папку собирает `./scripts/build-terminal.ps1`.
Результат — `target/terminal-dist`. Скрипт требует новый каталог вывода, чтобы
устаревшие файлы пресета не изменили content hash; для повторной сборки задайте
другой `-OutputDirectory`.

Клиент ждёт готовности именно своего дочернего процесса, пишет его вывод в
`.openheart-terminal/server.log` и останавливает его при штатном выходе, ошибке или
раскрутке panic. Подключённый внешний сервер не останавливается. После аварийного
уничтожения клиента дополнительная защита хоста — `-idle-exit 2m`.

## Управление

| Клавиша | Действие |
|---|---|
| WASD / стрелки | Движение; удерживайте клавишу |
| Tab | Выбрать следующего врага, начиная с ближайшего |
| Space | Атаковать выбранного врага, с проверкой дальности и стен |
| 1–8 | Выбрать имеющееся оружие |
| R | Перезарядить |
| Q / F | Две способности класса |
| E | NPC, портал, реле или эхо; удерживать возле поверженного союзника для спасения |
| Enter / 1–9 | Следующая реплика / ответ в диалоге |
| I / J / P / C / N | Инвентарь / задания / перки / рецепты / список NPC |
| + / − | Масштаб карты |
| PgUp / PgDn | Прокрутка панели |
| F1 / Esc | Помощь / закрыть панель |
| : | Командная строка |
| Ctrl+C / `:quit` | Сохранить и выйти |

Карта: `@` — вы, `&` — другой игрок, `e/E` — враг/элита, `*` — цель,
`$` — предмет, `N` — NPC, `#` — стена, `<` — выход, `>` — портал,
`?` — сюжетное эхо, `1/2/3` — реле. Подбор предметов происходит при приближении.
Панели не останавливают бой и серверный тик.

Примеры команд (вводятся после `:`):

```text
delve 2             войти в подземелье глубины 2
delve 2 7           присоединиться к забегу лидера с peer=7 в хабе
hub                 вернуться в хаб
talk vale           поговорить с NPC рядом
quest QUEST_ID      открыть доступное задание у его NPC
choose 1            выбрать ответ
buy medkit          купить аптечку рядом с торговцем
sell medkit         продать предмет рядом с торговцем
craft RECIPE_ID     выполнить рецепт, включая требования станции и флагов
perk PERK_ID        купить доступный ранг
respec              сбросить перки по правилам ядра
perkpoint           создать очко перка за материалы и золото
spec 2              выбрать специализацию один раз
use medkit          использовать лечебный предмет в одиночной игре
say Привет!         отправить чат
save                сохранить персонажа
```

Класс нового персонажа задаётся `--class 1|2|3` (Берсерк / Штурмовик / Оператор).
Сохранённый персонаж имеет приоритет. Для отдельного профиля используйте
`--data-dir другая-папка`. Идентификаторы предметов, NPC, рецептов и перков видны
в соответствующих панелях. Для общего данжа запомните peer лидера **в хабе**:
при переходе Go-сервер назначает новый peer.

## Авторизация и сохранения

Открытый сервер: достаточно `--nick`. Для локального аккаунта сервера:

```powershell
$env:OH_PASSWORD = 'ваш-пароль'
cargo run -p openheart-terminal -- --server ws://127.0.0.1:7777/ws --login alex --register
# При последующих входах опустите --register.
```

Для собственного хоста `--host --login alex --register` включает `auth=local`.
Мастер-тикет передаётся через `OH_TICKET`, пароль закрытого сервера — через
`OH_SERVER_PASSWORD`. Пароли не нужны в аргументах процесса. WebSocket TLS (`wss://`)
проверяет сертификат системным хранилищем доверия.

Сохраняется общий `SaveData` ядра: инвентарь, прогресс, задания, перки, оружие.
Автосохранение — каждые 30 секунд, при переходах/ответах и выходе.

- Одиночный персонаж: `.openheart-terminal/solo-PRESET.json`.
- Гость открытого сервера: отдельный локальный файл по адресу, пресету и нику.
  В существующем Go-сервере гости не имеют постоянного аккаунта.
- Авторизованный персонаж: сообщение `save` на сервер; `welcome.character`
  восстанавливается при входе. Соло-сохранение никогда не отправляется на сервер.
- Сохраняется персонаж; расположение врагов и середина незавершённого забега
  не восстанавливаются после закрытия одиночной сессии.

## Что перенесено и что пока отличается

Работают три режима запуска, WS/WSS, проверка content hash, общий данж для пати,
снапшоты игроков/врагов/лута, чат, переходы комнат, бой на общей симуляции,
способности, перезарядка, спасение союзника, данные пресетов, диалоги с условиями,
квестовые цепочки, торговля предметами, крафт, приобретение перков, сохранения,
статические предметы, реле и сюжетные эхо.

**Полного функционального паритета с Godot-клиентом пока нет.**

- Вид сверху заменяет FPS-рендер. Нет прыжков, точной физики рамп/цилиндров,
  прицеливания по частям тела, анимаций, звука и графического редактора.
- Бой следует текущему `core::sim`, как Go-сервер. Отдельные Godot-механики
  (альтернативный огонь, клиентские снаряды/сплэш, модификации оружия, hazards,
  боевые множители специализаций/перков) не перенесены в эту симуляцию.
  Выбор специализации и перков сохраняется, но полного набора их боевых эффектов нет.
- Сетевой протокол пока не предоставляет применение аптечки к серверному HP:
  клиент явно сообщает об этом и не списывает предмет.
- Нет меню списка серверов/обмена паролем мастер-аккаунта на тикет, динамических
  городских мини-игр, гардероба и creative-режима. Некоторые задания нового
  городского контента зависят от этих механик и пока не завершаются здесь.
- База аккаунтов сервера и формат протокола не изменялись. Статические предметы,
  диалоги и прогресс обрабатываются клиентом, как в текущем Godot-клиенте;
  это не новая серверная система валидации прогресса.

## Проверки

```sh
cargo test -p openheart-terminal
cargo clippy -p openheart-terminal --all-targets -- -D warnings
cargo run -p openheart-terminal -- --offline --headless --world delve --seconds 3
cargo run -p openheart-terminal -- --host --headless --seconds 3
```

Настоящий интеграционный тест запускает Go + WASM, подключает два клиента,
проверяет чат, общий сид/геометрию данжа, возврат в хаб, отказ при другом content
hash и закрытие порта хоста:

```powershell
$env:OH_TEST_SERVER = (Resolve-Path server/oh-server.exe).Path
$env:OH_TEST_CORE = (Resolve-Path target/wasm32-unknown-unknown/release/openheart_core.wasm).Path
cargo test -p openheart-terminal -- --include-ignored
```

Без переменных интеграционный тест пропускается; обычные тесты проверяют движение,
бой и округление HP, сохранения, условия диалогов, предметы, hash и терминальную
вёрстку через `TestBackend`. `--headless` завершается с ненулевым кодом при
отказе/обрыве/таймауте; успешный результат — строка `OK ... snapshots=N`.
